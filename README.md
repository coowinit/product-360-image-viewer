# 360° 产品图片序列预览组件

基于 **HTML + CSS + JavaScript** 开发的轻量级产品 360° 图片序列查看器。通过连续切换同一产品的多角度照片，模拟水平旋转展示效果，无需 3D 模型、GLB 文件或第三方 JavaScript 库。

适合产品详情页、企业官网、B2B 产品展示页面，以及图片序列交互技术研究。

## 功能特性

- **36 帧序列**：每帧相隔约 10°，组成一周 360° 水平旋转展示。
- **鼠标拖动**：在产品图片上左右拖动以切换角度。
- **触摸滑动**：支持触摸设备上的左右滑动操作。
- **自动旋转**：一键播放或暂停连续旋转。
- **正面 / 背面**：独立视图按钮，可直接跳转到第 1 帧（0°）与第 19 帧（180°）。
- **手动控制**：支持上一帧、下一帧、角度滑块，以及展示区的键盘左右方向键。
- **帧数反馈**：展示当前角度、帧数与进度。
- **响应式布局**：设计宽度为 800px，主要展示区域采用约 800 × 600 的视觉比例，并适配较小屏幕。
- **本地资源**：36 张 JPG、CSS、JavaScript 均在项目目录内，基本功能无需联网。

## 快速开始

1. 下载或克隆仓库。
2. 确保 `images/` 文件夹中包含 `img01.jpg` ~ `img36.jpg`。
3. 用浏览器直接打开根目录下的 `index.html`。
4. 在页面上拖动产品、切换正反面或点击「自动旋转」进行测试。

本项目是纯静态页面，**无需 npm、打包工具、数据库或本地服务器**。

## 交互说明

| 操作 | 效果 |
| --- | --- |
| 鼠标左右拖动 / 触摸滑动 | 切换连续图片帧，模拟产品旋转 |
| 360° 旋转 | 返回可拖动的旋转模式 |
| 正面 | 显示 `img01.jpg`（以第 1 帧为正面基准） |
| 背面 | 显示 `img19.jpg`（与第 1 帧相差 180°） |
| 自动旋转 / 暂停旋转 | 连续播放 / 停止播放帧序列 |
| 上一帧 / 下一帧 | 按 10° 步长调整 |
| 角度滑块 | 定位指定帧 |
| 展示区键盘 ← / → | 在 360° 模式下切换前后帧 |

**关于正反面：** 当前以第 1 帧和第 19 帧分别作为正面、背面。如果替换了另一款产品，请根据实际拍摄起点调整 `js/viewer.js` 中的帧索引，而不是默认每套照片的第一帧都是产品的实际正面。

## 替换为自己的产品图片

建议在固定机位、固定光线、固定产品中心的条件下，以约 10° 为间隔拍摄 36 张照片，形成完整的一周。拍摄时保持产品大小、视角、画面位置与背景一致，以减少切换时的跳动感。

将照片依次命名为 `img01.jpg` ~ `img36.jpg`，覆盖 `images/` 中的示例文件。图片命名规则位于 `js/viewer.js`：

```js
const TOTAL = 36;
const filename = index => `images/img${String(index + 1).padStart(2, '0')}.jpg`;
```

若改用 WebP，可以统一转换全部图片，再将文件扩展名修改为 `.webp`。不要只替换少数文件却保留不同的扩展名规则。

**图片尺寸提示：** 当前示例 JPG 的尺寸为 1005 × 600，展示区的目标布局约为 800 × 600；图片素材的宽高与页面容器尺寸不必完全一致。优先确保所有序列图片尺寸统一、主体始终居中。

## 实现原理

这套组件采用 **图片序列旋转（image-sequence / 360° spin）**，而非真正的三维模型渲染。

- 预先准备按角度排序的 36 张平面照片。
- 用户拖动时根据水平位移计算应显示的帧索引。
- 自动旋转通过定时切换帧索引实现。
- 图片预加载可降低切换时的等待感；最终流畅度仍受图片尺寸、设备性能和浏览器缓存影响。

它不支持任意改变俯仰角、查看未拍摄的底部或内部结构。若需要自由轨道旋转、材质与光照交互，应研究 GLB + `<model-viewer>` 或 WebGL 方案。

## 后续扩展建议

建议优先保持组件轻量、易嵌入和可维护。未来根据真实项目需要，再逐步考虑：

1. **性能优化**：将 JPG 批量转为 WebP，并根据实际页面情况优化预加载策略。
2. **组件封装**：将图片路径、帧数、播放速度、正反面索引改为可配置参数，方便复用。
3. **WordPress 集成**：封装为独立短代码或 Gutenberg 区块，用于产品详情页，不必直接修改主题核心逻辑。
4. **交互增强**：按需加入全屏查看、缩放或多组产品序列切换，避免过早引入不必要的复杂度。
